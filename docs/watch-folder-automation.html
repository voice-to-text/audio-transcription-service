Watch Folder automation and duplicate protection

Pick a local folder once and let the studio transcribe every incoming audio or video recording automatically.

Waiting for file copy completion

Copying a large MP4 video or podcast MP3 into a watched folder often takes several seconds. Starting transcription too early reads an incomplete file and triggers a decode error.

Audio Transcription Studio combines native filesystem events via Rust notify (FSEvents on macOS and ReadDirectoryChangesW on Windows) with a stability check. Each new file must report a non-zero byte size that stays unchanged across consecutive polling ticks for at least 700 ms and allow clean file opening before entering the queue. Temporary browser downloads (.part, .crdownload, .tmp) and output files (.txt, .srt, .vtt) are ignored.

SHA-256 duplicate protection

Every file entering the queue is hashed with SHA-256. After transcription succeeds, the hash and source path are stored in queue_state.json. Dropping the same file again or copying an identical recording under a new filename marks it as Skipped (Duplicate) without wasting CPU time running Whisper again. You can still override this manually with the Re-transcribe button on any item.

Sidecar TXT, SRT, and VTT exports

When recognition finishes, three files are written atomically next to the original media file: 

/path/to/recording.mp4
/path/to/recording.txt   (plain text transcript)
/path/to/recording.srt   (SubRip subtitles with HH:MM:SS,mmm timings)
/path/to/recording.vtt   (WebVTT subtitles with WEBVTT header)

If the destination directory is read-only or loses write permissions, the exporter logs a PERMISSION_DENIED entry in the Error Log and moves on to the remaining files in the queue.
